# 精读模板与批判性检查表

## 1. 五问速读（先答完再读细节）

1. **问题**：一句话说清论文要解决什么，以及为什么现在重要。
2. **洞察**：作者的关键观察/假设是什么？（通常是 Intro 最后两段）
3. **方法**：核心机制 5-10 行伪代码；标出与最强 baseline 的 1-2 个结构性差异。
4. **证据**：主表数字、消融、鲁棒性、效率（参数量/FLOPs/延迟）是否支持 claim？
5. **边界**：什么条件下方法会失效？作者承认了哪些局限？没承认但你能推断出哪些？

## 2. 笔记骨架

```markdown
# <标题>（<arXiv id>，<venue> <year>）
## TL;DR（≤3 句）
## 问题与动机
## 方法（伪代码）
## 实验设定（数据/指标/baseline/超参/硬件）
## 关键结果（表格引用 Table N）
## 消融与结论可靠性
## 批判与可迁移点
## 复现清单（代码/数据/命令/风险）
```

## 3. 批判性检查表

- [ ] baseline 是否是最新的、被调过参的？有没有「稻草人 baseline」？
- [ ] 主表是否同一数据划分、同一评测脚本？有没有 test-set 调参痕迹？
- [ ] 提升幅度是否有误差棒 / 多个 seed？是否只报最好 seed？
- [ ] 消融是否完整：每个模块单独移除 vs 组合移除？
- [ ] 计算成本是否可比（同参数量/同 FLOPs/同数据）？只比大模型是否不公平？
- [ ] 结论是否超出实验支撑范围（over-claiming）？
- [ ] 代码/数据/超参是否公开？复现风险：低 / 中 / 高。

## 4. 与自己的研究对接

- 可迁移点：哪个模块能搬到我的任务？成本多大？
- 可对标的实验：我需要在哪些数据集上报同样指标？
- 可引用位置：Intro 的动机、Related Work 的路线、Method 的对比、Discussion 的局限。
