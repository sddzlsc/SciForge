# 段落级写作模板与引用核验

## 1. Intro 的六段结构

1. **领域重要性**（2-3 句）：谁需要、用在哪、当前进展。
2. **现有方法**（2-3 句 + 引用）：主流路线与代表工作。
3. **具体局限**（2-3 句）：在什么设定下失败，为什么重要。
4. **我们的洞察**（1-2 句）：关键观察（通常配一张图）。
5. **方法一句话 + 贡献列表**：3 条以内，可验证。
6. **结果预告**（1-2 句）：关键数字。

反模式：开头大谈「深度学习改变世界」；三段都在列相关工作；贡献写成「我们提出一个框架」。

## 2. Method 段落模板

- **动机段**：现有设计在 X 条件的问题（引用/实验证据）。
- **设计段**：我们怎么做（公式 + 结构图引用）；解释每个符号。
- **为什么有效段**：直觉/理论/消融预告；避免只描述不复述原因。
- **实现段**（可放附录）：超参、训练细节。

## 3. Experiments 段落模板

- 设置：数据/指标/baseline（可放附录，正文一句带过）。
- 每个 claim 一段：`Table N shows ...`（结果）→ `This suggests ...`（解读）→ `We attribute ...`（原因）。
- 消融：`Removing X degrades Y by Z`，并解释 X 的作用。
- 诚实：报告失败案例/边界条件，提升可信度。

## 4. 引用核验流程（防幻觉）

1. 只从 `lit_search`/`paper_cite`/Semantic Scholar/OpenAlex 等接口取元数据。
2. 每条引用核对：标题、作者、年份、venue、DOI/arXiv ID。
3. 用 `paper_cite` 生成 BibTeX，不手写条目。
4. 不确定的引用标 `[CITATION NEEDED]`，投稿前必须清零。
5. 检查参考文献中是否有重复/撤稿/被取代的工作。
6. 不引用未读过的论文来支撑具体结论（可引用为「see also」但需准确）。

## 5. 写作反模式

- 形容词堆砌（novel/effective/significantly）代替数字与证据。
- 每段没有主题句，读者不知道这段在论证什么。
- Related Work 变成逐篇摘要，没有对比与定位。
- 过度 claim：实验只支持 64 帧，却声称「通用长视频」。
- 公式符号前后不一致；首次出现不定义。
- 图表数字与正文/abstract 不一致。
- 引用从记忆生成（幻觉率极高，学术不端风险）。

## 6. 审稿人 checklist 自问

- 贡献是否清晰、是否被实验支撑？
- baseline 是否公平、最新？
- 消融是否完整？
- 是否讨论局限与失败？
- 可复现性（代码/数据/超参）是否充分？
