# 数据泄漏与评测公平检查清单

## 1. 泄漏来源排查

| 来源 | 检查方法 | 处理 |
|---|---|---|
| 训练/测试重复样本 | 精确 hash 去重 + MinHash/embedding 近重复 | 删除训练侧重复样本后重跑 |
| 预训练语料污染 | 用测试集 n-gram/题目去匹配预训练数据（若有） | 报告污染比例；用去污染子集 |
| 测试集参与调参 | 检查超参选择记录与 early stopping 依据 | 只用 dev 选参，test 只评一次 |
| prompt 泄漏答案 | 检查 few-shot 示例是否来自 test、模板是否含标签 | 从 train/dev 取示例 |
| 数据划分不独立 | 检查同源样本（同一视频/同一病人）是否跨 split | 按 group/来源划分 |
| 指标实现 bug | 用已知结果的 toy case 单测指标 | 对齐官方实现 |
| 后处理过拟合 | 检查阈值/规则是否在 test 上调过 | 在 dev 上调，test 冻结 |
| 重复评测（test 多次） | 记录 test 评测次数 | 只报最终一次；或多 seed 但不挑最好 |

## 2. 近重复检测（无第三方库版本）

1. 文本：字符 5-gram Jaccard / MinHash（`hashlib` + 分桶），阈值 ~0.8。
2. 图像：感知 hash（dHash）+ 汉明距离 ≤5 视为近重复。
3. 视频：抽 8 帧算 dHash 平均距离。
4. 代码/数学题：归一化后 exact match + AST 结构相似。

## 3. 公平比较表

| 维度 | 要求 |
|---|---|
| 参数量 | 报告总参数/可训练参数；不同规模分档 |
| 训练数据 | 同数据量或明确标注；不许「我们数据多 10×」还直接比 |
| 评测预算 | 同 max tokens/同推理次数；不同则分表 |
| 硬件 | 记录 GPU 型号；影响吞吐但不影响精度 |
| 调参预算 | 同搜索空间/同次数；或报告各自最优 |
| 显著性 | 配对 bootstrap 或 t-test，报告 p 值/CI |

## 4. 结果可信度自查

- [ ] test 集合在最终实验前从未使用。
- [ ] baseline 数字来自官方脚本或作者确认。
- [ ] 同协议重跑所有方法（不是引用不同论文的数字混用）。
- [ ] 报告 seeds、均值、标准差。
- [ ] 异常好的结果先按本清单排雷再庆祝。
- [ ] 论文中写明评测协议与脚本版本。
