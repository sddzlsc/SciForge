# 学术报告与 Slides（Slide Talk）

## 何时使用（触发条件）

- 组会/开题/答辩/会议 oral/poster 需要制作 slides 与讲稿。
- 已有论文或实验结果，需要压缩成 10-20 分钟叙事。
- 需要把复杂方法讲给非本方向听众，或准备 reviewer 问答。

## 输入 / 输出

- 输入：论文/实验材料、听众背景、时长、场合（组会 20min / 会议 12min / poster 90s pitch）。
- 输出：slide 大纲（每页标题 + 3-5 个要点 + 配图）、逐页讲稿、时间分配表、预期 Q&A 清单。

## 工作流

1. **确定主线**：一句话 takeaway（听众离场后记住什么）；所有页面服务这一句。
2. **按时间配页**：12 分钟约 10-14 页；结构 = 问题/动机（2-3 页）→ 现有方法局限（1-2 页）→ 方法（3-4 页）→ 结果（2-3 页）→ 结论/展望（1-2 页）。
3. **每页一个论点**：标题写结论（「Memory 模块把 FVD 降低 18%」），正文 3-5 个短要点，图占 60% 面积。
4. **方法页抽象化**：先用一张总览图讲数据流，再用 1-2 页讲最关键机制；细节留到 backup slides 应对提问。
5. **结果页**：放主表/主图 + 一句解读；不要读数字表，讲趋势与对比。
6. **配图复用**：从论文 `figures/` 取图，重新排版成大字号（正文 ≥18pt，图内文字 ≥12pt）；单页信息密度减半。
7. **写讲稿 + 排练**：每页 45-90 秒；标记过渡句；排练 2 次控制时间；准备 5-10 个 Q&A。

## 质量检查清单

- [ ] 第一页/第二页就讲清问题与贡献，不铺垫太长。
- [ ] 每页只有一个核心信息，标题即结论。
- [ ] 字号足够（正文字号 ≥18pt），后排可读。
- [ ] 图有来源标注，坐标轴/图例可读。
- [ ] 时间分配合理，留 20% buffer 给提问。
- [ ] 有 backup slides：超参、消融、失败案例、相关工作对比。
- [ ] 动画/切换不喧宾夺主；无大段文字。
- [ ] 讲稿口语化，过渡自然，不照读 slides。

## 失败处理

| 情况 | 处理 |
|---|---|
| 内容太多讲不完 | 砍到一条主线；细节进 backup；每页只留一个论点 |
| 听众背景不同 | 前 2 页补背景与直觉示例；术语第一次出现给比喻 |
| 图太小/太复杂 | 重画简化版；截取局部放大；正文只讲趋势 |
| 紧张忘词 | 每页标题即提示；写关键词而非逐字稿；排练计时 |
| 被问倒 | 承认不确定 + 给出后续验证计划；不要编数据 |
| poster 讲不完 | 准备 30s / 90s / 3min 三个版本，按听众兴趣切换 |

## SciForge 工具与 CLI 对应

| 步骤 | 工具 / CLI |
|---|---|
| 生成大纲/讲稿 | LLM 对话（`sciforge chat`）、`paper_section` |
| 复用论文图 | `figure_architecture`、`figure_plot`、`figure_table` |
| 材料整理 | `paper_review`、`exp_results` |
| 外部生态 | `easyslides`（Rimagination 生态，见 catalog）、`scientific-slides`（k-dense 生态） |

## 示例

```bash
sciforge chat "把 paper/main.tex 压缩成 12 分钟会议 talk 大纲：每页标题+3 个要点+配图建议+45 秒讲稿"
```
